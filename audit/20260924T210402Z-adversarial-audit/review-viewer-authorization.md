## Outstanding integration item

**Plugin alias/name precedence — pending, no execution bypass established.** In `bot.py` (`_execute_tool_by_name` alias normalization and `_turn_tool_names` / `_tools_for_turn`), plugin names remain out of `self.tools`, while arbitrary enabled plugin names can be included in the turn catalog. A plugin named `bash` or `run_command` can therefore pass the catalog policy as a nonprivileged raw name, but dispatch rewrites it to `shell` before plugin lookup and applies the shell gate. A non-admin cannot execute shell this way; the advertised plugin schema is instead unreachable or describes a different tool than dispatch will invoke. The parent reports that exact-plugin-name-before-alias precedence, with built-in precedence, is accepted but still awaiting integration. Recheck that change before closing the contract.

The retired external-text confirmation gate is deliberate and is not proposed for restoration.
- **C-31:** the audited `MSG INFO` entry now contains user/channel IDs, a guild ID or the fixed `DM` label, and a character count—not names or raw message text. The former message-content framing route is absent from this entry.
- **C-32 / C-33:** true framing loss (`line is None`) fails closed with persistent continuity loss; bounded redactor-state overflow also fails closed. Fully scanned malformed, structural-depth, and overlong-service rejection paths do not set that latch; their original bytes are scanned before the per-record rejection. If the scanned line itself opens a PEM/config redaction span, it remains a redaction event rather than a continuity-loss event; this review does not claim that every such redacted line is represented as a separate omission marker. Viewer omission markers use the viewer-owned scope and scrub source text/service/logger metadata. The static errors view includes viewer markers, and append visibility plus scope-specific T/P replay preserve viewer markers. `AppendHistory` serialized-budget markers are likewise viewer-scoped.
- **Redaction-state continuity:** complete typed JSON values use record-local PEM/config scanning, while an already-active outer plaintext span still hides the complete typed record and cannot be cleared by an embedded JSON end marker. The corrected `EventParser` path covers JSONL as well as the append parser; malformed/rejected fragments are scanned from their original text before fallback redaction. The final BEGIN/END ordering logic keeps a later BEGIN open when one line contains an earlier END followed by a new BEGIN. Existing source fixtures exercise both parser consumers, generic and image records, active outer spans, and the marker-order case.
- **Error-group coalescing — not a confirmed defect:** I retract the earlier concern that the storage-budget marker must terminate its original open producer-error group. The marker represents that producer group, and existing history coverage deliberately keeps an unlevelled continuation attached. Recognized producer boundaries (timestamp, level, or non-text kind) still close the group; no such boundary being absorbed was established. Bare unlevelled text is continuation-eligible under the existing grouping contract, so it cannot be called an ordinary new record from these fields alone.
