## C-36 — operator lifecycle

- `restart` now inspects an owned container's bounded state before private preparation and refuses any non-running state. Its error preserves status, exit code, OOM flag, finish timestamp and image reference and points the operator to logs and the **explicit** `start --replace` action. It never removes a container on restart. A running owned container still takes the existing explicit Docker restart and readiness path.
- `status` reads owned Docker metadata first, retains exit/OOM/finish evidence even when derived config or independent bridge/private-layout validation fails, and reports generic credential-safe config-unavailable and embedding-check-skipped reasons. Bridge failure does not fabricate an endpoint; layout failure reports an endpoint only after bridge validation. Container ownership/name and state-inspect errors are **not** caught or converted into trusted metadata. The docstring distinguishes metadata/config reads from the in-container `docker exec` embedding check; this lane did not execute any of them.
- The cited `derived_config` endpoint-failure branch was **already gated** by `if enabled` (`scripts/dirac.py:202–208` at the inspected source). No gating change was made. The existing case now covers an intentionally mismatched endpoint with RAG disabled.

## C-37 — smoke settlement

- Parent's `ReplyQueue.cancel_message_with_task(channel_id, message_id) -> tuple[bool, asyncio.Task | None]` supplies an exact, synchronous task receipt. This runtime consumes that API directly: queued removal `(True,None)`, registered pre-start running task `(True,task)`, already-done matched task `(False,task)`, and no match `(False,None)` have different settlement implications. No private queue-state inspection or old bool-only fallback was added here.
- After any exception **following observer.open**, including a protocol exception, the handler cancels only the input's exact queue entry/task; the registered or observed task gets a bounded settlement wait. It writes a terminal provisional *settlement unconfirmed* result before awaiting cleanup, refreshes actual `returned` and delivered IDs after that wait even on subsequent cancellation, and removes the provisional qualifier only after confirmed settlement. An unresolved live task holds the `_stuck` admission gate; unresolved taskless injection stops polling rather than guessing success. When the bot's message handler has returned normally with no matching queue entry or started observer turn, its synchronous directed-admission path supports a genuine no-turn gate/drop result; that combination, not `(False,None)` alone, permits the next smoke.
- Stop/fatal cleanup does not equate `turn.task is None` with a settled input. If polling can still resume an in-flight injection, hooks and observation stay installed until its outcome is known. Already-started Discord/remote sends are not retracted by cancellation; the notice-send-started case records unknown delivery without claiming a notice ID. A lost answer-send acknowledgment is likewise not proof Discord received nothing: `_Turn.delivered` holds only observed response IDs, and failed terminal receipts say unacknowledged sends, **if any**, may still have reached Discord, including when earlier chunks have confirmed IDs. No fabricated ID or completion is recorded. Request deadline expiration remains distinct from an ordinary upstream `TimeoutError`. A completed outcome written before optional readback is never downgraded; `CancelledError` is re-raised.
