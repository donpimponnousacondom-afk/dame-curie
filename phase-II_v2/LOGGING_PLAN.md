## 3. Proposed operator contract

### Modes and compatibility

First stage adds **opt-in `--format screen`** to the existing logs selection, without changing `auto`, `console`, `plain` or `jsonl` behavior. The new mode is append-only on the ordinary terminal screen: no alternate buffer, cursor positioning, erase, carriage-return status line, screen clear or terminal-title sequences. Only viewer-generated SGR colors are allowed. It prints a short help/status banner, then appends new events/notices. Earlier rows are never rewritten. GNU Screen scrollback is finite and owned by Screen, separate from the viewer's bounded history.

`screen` with non-TTY input/output emits terminal-control-safe, known-pattern-redacted plaintext with no key reader, terminal-mode changes, ANSI or implicit `/dev/tty` access. TTY keys additionally require the viewer to own the terminal foreground process group. Proposed `--no-keys` is valid only with `logs --format screen` and overrides TTY eligibility; reject it for unrelated actions/modes rather than silently changing old behavior. `TERM=dumb`/unknown and `NO_COLOR` disable colors; missing full-screen terminfo must not disable append-only output. Plain legacy output remains explicitly **not a safe-redaction export**. Existing JSONL v1 remains available; a later opt-in structured transport must not silently change that schema.

Rows retain Hortator's useful contract: timestamp + severity + scope + event kind + labelled local sequence + present correlation IDs + concise fields. Color severity, scope and correlation/field tokens, not only the timestamp; the identical plaintext row remains readable without color. Preserve full timestamp/provenance in selected evidence. Do not fabricate `#ledger_seq`, turn/request/job IDs or provider metrics absent from the source.

After separate acceptance, root may choose whether `auto/console` should select the new mode. Until then no default switch. No Screen configuration edits are required or authorized.

### Exact proposed keys (all local, case-sensitive)

| Key | Action |
| --- | --- |

| `s b p d t c w a` | Toggle system/bot/provider/Discord/tool/context/web/subagent display scopes respectively. `a` is **not** a provider alias here. |
| `o` | Toggle already-received Ollama rows, hidden by default; never contact/start/pull Ollama. |
| `f` | Toggle folding and append an explicitly labelled replay of up to five retained matching events. Never rewrite prior rows. |
| `T` / `P` | Cycle tool/provider summary→sanitized metadata/JSON→retained evidence; replay the latest matching event. No databases, request bodies or private diagnostics fetched. |
| `r` | Pause live display; append up to 20 retained matching events (oldest→newest); pin newest as selection. |
| `e` | Pause; append up to 20 retained WARNING/ERROR/CRITICAL or recognized failure events. Ignore scope/severity/Ollama visibility deliberately and say so in the heading, so hidden errors remain findable. This broadens the current errors-only list, explicitly. |
| `[` / `]` | Reference older/newer keys; `L` / `l` are proposed aliases for root's reported labels. Navigate a frozen candidate set, clamp with a notice, never jump to a live arrival. |
| Enter | Pause and append page one of selected retained evidence (latest matching event if none). |
| `n` / `N` | Next/previous page of the **same pinned sanitized snapshot**; append a page header and bounded block. Clamp at ends with notice. |
| Space | Pause/resume live display, not ingestion; on resume report unseen/evicted counts, replay at most 20 retained unseen matching events, then follow new arrivals. No unlimited catch-up dump. |
| Esc | **No standalone command in new mode**; reserved for sequence parsing. Space resumes. Legacy full-screen Esc behavior remains unchanged. |
| `i` | Append local viewer state: mode/filters, retained/evicted/omitted counts, source status, queue lag/gaps and actual correlation coverage. **Not runtime inspection.** |
| `0` | Reset display controls to INFO/all scopes/folded/summary depths/Ollama hidden; clear selection and resume with bounded catch-up. Does not clear history or mutate producer settings. |
| `?` / `h` | Pause and append help; evidence paging keys also page a frozen help snapshot. |
| `q`, Ctrl-C, Ctrl-D | Exit viewer (Ctrl-D is an explicit cbreak key; it is not kernel EOF in this mode). Actual input EOF, SIGTERM or SIGHUP also leave cleanly. Never stop the bot/container. |

**Deliberate departures, not claimed Hortator behavior:** Space pause, Enter inspection, viewer-only quit, local `i`, no private stored evidence, warning-inclusive **unfiltered** `e`, immutable/eviction-aware selection and reserved Esc are new/local contracts. Reference `e` applies current filters; current dame-curie error history ignores them. Reference `a` aliases providers; retain dame-curie's subagent key. For `f/T/P`, follow stays follow unless paging/navigation starts. As in the reference, `f` expansion raises effective detail to at least JSON; a T/P evidence setting raises it further. Live detail previews never replace the selected snapshot. `r/e/T/P` freeze up to 500 eligible candidate IDs, print their bounded replay and select the newest; `[/]` from live first freezes the current eligible set. Filter changes affect future live/replay selections, not an existing pinned set. Pausing suppresses ordinary live rows, not explicit replay notices.

GNU Screen retains its prefix, default `Ctrl-A`: `<prefix> [` enters Screen copy mode; copy-mode navigation/quit keys belong to Screen, not this viewer. Standalone `[` reaches the viewer only outside copy mode. Do not bind Ctrl-A or interpret it as a command; a passed-through prefix byte is ignored. A user-remapped prefix is Screen's concern: the viewer sees only bytes Screen passes through, so a prefix remapped to `q`/Space can make that viewer key unavailable. No live Screen config was inspected. Recommend **viewer Space, then Screen copy mode**, so reading is stable even where Screen buffers or throttles output; resume after leaving copy mode. The viewer cannot reliably detect Screen copy mode. Do not promise wheel/terminal scrollback behavior independent of Screen configuration.

## 4. Data, terminal and pressure invariants

- **Independent viewer lifecycle:** follow only the existing explicitly selected logs source, never attach bot stdin or launch the bot in the same process group. New `screen` mode gives the owned logs follower DEVNULL stdin, including when keyboard controls are disabled. Changing noninteractive legacy-mode stdin is a separate opt-in fix, not smuggled into the compatibility promise. Preserve `start_new_session=True`; only the viewer-owned logs client's process group may be signalled, never an arbitrary command/producer/container. Ctrl-C ends viewer/follower only. Distinguish requested quit/BrokenPipe from an unexpected nonzero source exit. Finish terminal restoration before follower shutdown/output; proposed EOF output grace is 250 ms, follower TERM grace 5 s then KILL/reap grace 1 s, with incomplete cleanup reported rather than hidden unbounded `Popen.__exit__`/wait. A clean EOF that cannot flush admitted output is incomplete, not successful lossless export. Ordinary EOF/exception/SIGINT/SIGTERM/SIGHUP restores exact saved termios and signal handlers. For this minimal slice, retain and document existing Ctrl-Z/SIGTSTP behavior: restore and exit the viewer, not suspend it. No new suspend/resume state machine. SIGKILL cannot be restored by any program.
- **cbreak, not raw:** preserve ISIG and Screen prefix coexistence; Ctrl-C arrives as SIGINT, so exit must not depend on receiving byte `0x03`. Never consume stdin when it is the data source, non-TTY, backgrounded, or owned by the application. Check foreground process-group ownership before each key read, not only startup; loss of ownership stops key reads and triggers controlled lease cleanup/exit (SIGTTIN/SIGTTOU handling needs the synthetic job-control check). A future stdin-replay entry must disable keyboard input rather than open another TTY implicitly. No bot/provider/config bootstrap imports or store binding in the viewer. Existing `safety.py:7` imports `error_reporting` redaction; source shows standard-library imports and `_store=None` (`error_reporting.py:1-50`), not a configured store. Keep that audited helper dependency explicit rather than claiming the viewer currently imports no application support code.
- **Input is a stream, not keystroke-sized reads:** new append mode owns a binary `Popen` stdout pipe (`text=False`) and bounded `os.read` ingress; never touch its TextIOWrapper/iterator or reuse the unbounded JSONL text path. Preserve split UTF-8 through framing; discard oversized input through its delimiter with a marker. New keyboard parser reserves ESC, carries CSI/SS3/OSC/DCS/paste state across reads, and consumes complete sequences without dispatching suffix letters. Do not timeout back into ordinary commands midway. Bound sequence-prefix state to 64 bytes and incomplete-sequence age to 2 seconds; discard control/paste bodies incrementally. On malformed prefix/timeout, latch a visible `keys disabled: incomplete control sequence; Ctrl-C exits` state for this viewer session and discard subsequent key bytes without dispatch; never reinterpret a delayed suffix as a command. Lone ESC/Alt is not a resume gesture and may trigger this fail-closed state. ISIG Ctrl-C remains available; restart the viewer to reacquire keys. Ignore complete arrows/Alt sequences and never ASCII-decode non-ASCII bytes into possible keys. Honor received bracketed-paste markers but do not claim protection when Screen/terminal does not send them. Unmarked pasted ASCII is indistinguishable from typed keys; use no-keys mode where this matters.
- **Terminal injection/resize:** redact complete bounded records first; neutralize payload controls (including CR, ESC, C0/C1, bidi controls), then wrap/page, then apply viewer-owned colors. Prefix multiline detail rows so payload cannot impersonate headers. Split UTF-8/escape sequences and invalid bytes must not execute controls or crash output. Read size for the next append; never redraw older rows. Pin evidence text and page offsets at selection; a resize affects new snapshots, not content/navigation of the selected snapshot. Explicitly handle tiny terminals; existing per-codepoint width is not full Unicode grapheme correctness.
- **Proposed admission budgets:** pending input ≤2 MiB; shared history ≤500 normalized records AND 2 MiB serialized evidence; one immutable selected/help snapshot ≤512 KiB sanitized UTF-8 plus ≤500 candidate sequence IDs; rendered queue ≤128 blocks AND 256 KiB, including one ≤64 KiB partially-written block; repeat map ≤500 entries with bounded ≤256-byte keys. These bound retained data only, not total memory/RSS. Build evidence incrementally into its 512 KiB sanitized budget; do not concatenate a whole error/history group and truncate afterwards. Parse/redaction copies from a bounded input record remain transient overhead; cap nesting/serialized expansion explicitly or emit an omission record when safe bounded normalization cannot finish. Exact RSS and latency require later measurement, not source-only certification. Pages cap at 6,000 characters/80 rows and fit the selected terminal geometry; snapshots exceeding their cap carry an explicit partial marker. A pinned snapshot remains stable after ring eviction; selecting a different evicted candidate reports unavailable instead of jumping. No second error-history payload ring; `e` indexes the shared budget.
- **Ordering/concurrency:** one viewer writer serializes blocks. Assign monotonically increasing **viewer-local receive sequence**, distinctly labelled from producer IDs. Preserve sequence order among admitted LIVE blocks; priority REPLAY/help/notices are explicitly labelled out-of-band and may precede queued live rows, so no global display-order claim. Replay retains original timestamps/sequences and a separate replay label. Track live display drops separately from replay omissions, with bounded count/first-last affected sequence (not a false claim that every sequence in that range was lost). Don't sort by wall clocks or claim cross-service causal order. If reusing per-service legacy error grouping, every grouped heading/evidence page must say `HEURISTIC SAME-SERVICE CONTINUATION — NOT REQUEST-CORRELATED`; each fragment keeps its own metadata and is not assigned the first record's IDs. `boundary=next-record` is framing, not proof the logical error ended. Alternatively retain legacy fragments separately. Never present proximity/model-name matches as request evidence. New producer events should be one JSON object per record with escaped embedded newlines.
- **Pressure/writer:** pause cancels whole unsent live blocks and stops new ordinary display blocks, not source ingestion; an already partially-written block may finish. Record the suppressed range and catch up from the completed-display watermark, not merely the source's newest received sequence. Use one readiness-driven, nonblocking byte writer with partial-write offsets, no synchronous `TextIO.write/flush` in the ingest/control loop. Save exact `F_GETFL` and termios state before changes and restore both; changing a duplicated descriptor's flags also affects its shared open-file description. Explicitly cover stdin/stdout sharing a TTY and ensure the sole writer has stopped before cleanup. Never reopen a hidden TTY. If safe nonblocking setup is unavailable, do not silently claim interactive guarantees. Proposed loop quotas: inspect signal/stop state first (never queued); consume ≤64 key bytes, ≤16 KiB source bytes/≤16 completed records, then write ≤16 KiB per iteration; selector idle wait ≤100 ms. Partial framing work remains within input caps. Record actual quit latency later rather than promising hard real-time behavior. Evict only whole unsent live blocks, never the middle of a block; retain bounded gap counts/ranges and emit notice when writable. User replay/pages have priority; if they cannot be admitted, report busy when possible without advancing page state. Quit/signals restore terminal first and abandon pending output rather than wait for a blocked TTY; reset-color output is best effort, not a cleanup prerequisite. On broken pipe end the viewer and its owned follower only. Sustained overload can lose display/history evidence; original log retention is independent and finite. JSONL is never display-coalesced: preserve v1 behavior separately; any future bounded export must emit explicit gap/oversize records or fail visibly.
- **Repetitions:** only display-level suppression, first occurrence immediately plus count/first/last receive sequence and original timestamps after 30 seconds or flush. Start with the existing exact health recognizer; don't copy Hortator's broad warning/error suppression. Do not collapse distinct request/job/tool IDs or mutate history/JSONL/incident/memory records. Append an out-of-band `REPEAT` row carrying those fields. Use the new receive counter, not `HistoryEntry.sequence` (continuations share entry IDs); bound the map and never replace old rows.
- **Redaction/persistence:** current viewer sanitization happens after Docker persistence. New structured producer diagnostics must use allowlisted metadata and producer-available secret redaction **before stdout/file persistence**, with replay defense in depth. No raw fallback on parse/sanitization failure. Redact before truncation/pagination; explicit omitted/truncated/redacted flags distinguish unavailable data from folding. Full prompts, private messages, reasoning, headers, configuration and arbitrary tool output are not default diagnostic fields. This does not authorize sanitizing/pruning the functional REM/RAG store or claim historic/opaque secrets are removed.
