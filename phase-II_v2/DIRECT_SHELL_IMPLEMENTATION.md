## Implemented

- `ShellTool` launches `bash -lc` directly in the existing bot container, using `/home/dame-curie` as cwd and explicit subprocess HOME. It requires both the existing `DAME_CURIE_CONTAINER_MODE=true` flag and `/.dockerenv`; there is no host-execution fallback.
- Each command has its own session/process group. Timeout, cancellation and failed stream execution send TERM, allow the existing 0.2-second grace period, then KILL the group and reap the shell. Existing cancellation-shielded cleanup, stdout/stderr pumps, diagnostic capture, output budgets, timeout configuration, result markers, progress and Discord attachment delivery remain.
- Removed Docker CLI orchestration, nested image/container creation, Docker ownership/host-path translation, PID-file wrappers, full-host mode, shell regex blocklists and heredoc syntax restrictions. Empty-command and size-budget handling remain; Bash handles its own syntax.
- Removed CreateSite/EditSite/SiteServer/SiteTest/DeleteSite/ListSites and their exclusive file-writing, CSP, quota, expiry, graph-note, browser-probe and read-loop machinery. Their schemas, result catalog and default catalog entries are removed. Bot changes are narrowly class imports and registration. Generic Guide remains registered independently, without promising `site_test`.
- Removed stale create_site instructions from image result text and the local web-service URL from FetchUrl's description. No generated bytes, image URLs, local image paths or sidecar behavior changed.
- Aligned existing shell, attachment, diagnostics and mixed image/prompt fixtures; removed the two dedicated site-tool fixture files. No new test cases or feature-absence tests were added. Generic tool-call parser fixtures remain, including historical tool names as parser data.

## Review limits and unresolved behavior

- Source changes are ready for coordinated integration, not activation. Cancellation/process-group behavior, actual image HOME/symlink/UID permissions and Discord attachment delivery have not been exercised here.
- Ordinary pipelines and children remain in the command group and are signalled. A deliberately detached `setsid` child can escape that group; successful commands can also leave detached background processes. No process supervisor or cgroup layer was added. Outer-container shutdown/resource limits remain necessary.
- Approved direct shell shares the bot's user, readable mounts and environment. It is not an isolation boundary from same-user bot secrets. Generic send_file still refuses direct private paths, but arbitrary authorized shell can copy readable data into export roots. That is a consequence of the approved same-container design, not a broadened send_file allowlist.
- Existing long capture/progress methods and existing unrelated broad exception handling were retained rather than refactored. Newly rewritten process termination is small, uses specific ProcessLookupError suppression and adds no blanket catch or Any annotations.
- Existing `tests/test_create_site_unescaped_quotes.py` includes a historical optional private `/root/.hermes` fixture read, and the repository has other import-time dotenv hazards. None of these tests were run; future test execution still needs separately authorized synthetic/private-read isolation.
